Reducio

May 16, 2025

Often times, I need to compress videos either to meet file size limits (Discord!) or just to speed up uploads.

Sometimes I upload them to some online compressing tool. Othertimes, I rely on ffmpeg to compress them locally. Mostly due to privacy concerns (or) due to their huge sizes (uploading takes lot of time).

When I go through ffmpeg route, I end up googling the same command from StackOverflow. Every. Single. Time.

This one in particular: https://unix.stackexchange.com/q/28803/420712

I wanted a no-nonsense way to compress videos. Just drag and drop. I felt, there are other people out there who want the same.

So, I built Reduccio, a tiny app that does just two things:

  • 📦 Compress Audio/Video files.
  • 🔇 Removes Audio track from video files.

That’s it.

No command line. No upload limits. No nonsense. Just drag, drop, done; all offline.

Tech

I evaluated a few options before settling on Flutter to build desktop GUI.

  • Electron is too bloated. No one wants to download a 100MB app just to compress videos. Not to mention, it uses 80MB RAM even when it’s not in use.

  • Tauri is an interesting choice. I almost settled on it. I even started with Tauri. Then I got an error:

    TAURI g_uri_get_scheme: assertion 'uri != NULL' failed

    There’s an open issue on tauri repo for this, and none of the solutions in the comments worked for me. And, I haven’t seen any maintainer/contributor responding to this issue. So sad. Moved on from this. If this would have worked, I would have actually learned Rust for this.

  • What are we left with? Python’s Tkinter & Flutter desktop. Python’s tkinter is decent, but it’s UI is like bad. Like, 1990s bad. So, flutter it is.

And, Without mention, I used ffmpeg to compress videos.

Functionality wise, It’s not that complex (except UI).

I’m basically using this command:

ffmpeg -i input.mp4 -vcodec libx264 -crf 20 output.mp4

and conditionally controlling crf based on user’s desired compression level. Higher the CRF, Higher the compression, lower the quality.

I could have used libx265 instead of libx264 for better compression ratio. BUT, some platforms cannot play this format. libx265 is released in 2013, and Older hardware do not support decoding it. Some users have reported in iOS and HTML5 which are not that old surprisingly.

don’t use libx265 if you plan to use it on html5 video, see https://gist.github.com/Vestride/278e13915894821e1d6f#support.

So, I sticked with libx264. And rest of it is, calling ffmpeg through dart and passing apppropriate arguments.

// Video Settings
if (_keepOriginalVideo) {
    ffmpegArgs.addAll(['-c:v', 'copy']);
} else {
    ffmpegArgs.addAll(['-c:v', 'libx264']);
    ffmpegArgs.addAll(['-preset', 'medium']);
    int videoSliderIdx = _videoQualitySliderValue.round();
    if (videoSliderIdx == 0) ffmpegArgs.addAll(['-crf', '28']); // Low
    else if (videoSliderIdx == 1) ffmpegArgs.addAll(['-crf', '23']); // Medium
    else if (videoSliderIdx == 2) ffmpegArgs.addAll(['-crf', '20']); // Good
    else if (videoSliderIdx == 3) ffmpegArgs.addAll(['-crf', '18']); // High
}

// Audio Settings
if (_keepOriginalAudio) {
    ffmpegArgs.addAll(['-c:a', 'copy']);
} else {
    ffmpegArgs.addAll(['-c:a', 'aac']);
    int audioSliderIdx = _audioQualitySliderValue.round();
    final bitrates = ['64k', '96k', '128k', '192k', '256k', '320k'];
    if (audioSliderIdx >= 0 && audioSliderIdx < bitrates.length) {
        ffmpegArgs.addAll(['-b:a', bitrates[audioSliderIdx]]);
    } else {
        ffmpegArgs.addAll(['-b:a', '128k']); // Fallback, should not happen with slider
    }
}

ffmpegArgs.addAll(['-y', _outputFilePath!]);

One day, I was working while listening to music plugged in. I don’t remember the name of the song. I had to record a video of my screen to report a bug. I recorded it with OBS, dropped it in Discord.

You know what happened?

The audio from my music got recorded in the video. And I haven’t noticed it even after playing the video, because I thought that audio is just me listening to music. How stupid am I?

Anyway, nothing happened. Everyone just ignored it.

BUT BUT, If something like this happens, We don’t need to record the video again. We can just remove the audio track from the video. And yes, ffmpeg can do that too. Which means, I can add this feature to Reducio.

With these two features, Reducio is complete.

Building for other platforms

Flutter is cross-platform, meaning, same code can run on Linux, Windows and MacOS. I just need to build it for each platform. You know, like a nice executable. .exe for Windows, .app for MacOS, .deb/.AppImage for Linux.

I did it for Linux and released it as AppImage here: https://github.com/CITIZENDOT/reducio/releases/tag/v1.0.0

And Lastly, If we build Flutter App on Ubuntu 24.04.2 LTS, it will not work on Ubuntu 22.04.2 LTS. There’s an issue here: https://github.com/flutter/flutter/issues/145405, and it’s not being worked on. We can write the code, debug it on 24.04, and then build (production build step) it on 22.04.
